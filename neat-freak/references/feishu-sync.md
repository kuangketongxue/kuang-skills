# 飞书 Base ↔ 本地 Wiki 双向同步规则

> neat-freak 飞书同步的执行手册。每次 neat-freak 执行时读取此文件。

---

## 同步架构

```
本地 wiki/topics/*.md  ←→  飞书 Base 表
      （知识框架）           （结构化数据）
```

**核心原则**：
- wiki 存**知识框架和方法论**（给人和AI读）
- Base 存**结构化数据和追踪记录**（给系统计算用）
- 两边都要保持最新，不能只更新一边

## 同步流程

### 方向1：wiki → Base（知识写入）

**触发条件**：wiki/topics/ 文件被修改（新增或更新内容）

**执行步骤**：
1. 读取修改的 wiki 文件内容
2. 提取新增/更新的知识条目
3. 在对应 Base 表中搜索是否已存在（按标题/关键词匹配）
4. 已存在 → `+record-batch-update` 更新
5. 不存在 → `+record-batch-create` 新增
6. 输出：新增X条，更新Y条

**字段映射**（浪前前哨战表为例）：

| wiki内容字段 | Base字段 | 类型 |
|-------------|---------|------|
| 标题/章节名 | 标题 | text |
| 核心观点 | 核心观点 | text |
| 操作步骤 | 行动指引 | text |
| 来源标注 | 来源 | select |

### 方向2：Base → wiki（数据回写）

**触发条件**：Base 表数据发生重大变化（如周/月汇总、阶段性结论）

**执行步骤**：
1. 读取 Base 表最新记录
2. 提取汇总数据（如月度收入统计、分数趋势）
3. 更新对应 wiki 文件的"当前状态"或"关键数据"章节
4. 不覆盖 wiki 的知识框架部分，只更新数据部分

**示例**：
- Base1 赚钱表新增收入记录 → 更新 `赚100万.md` 的"当前状态"章节
- Base2 每日追踪新增分数 → 更新 `高考上清华.md` 的"关键监控指标"

### 方向3：公式健康检查（每次 neat-freak 必做）

**执行步骤**：
1. 对每个 Base 的每张表，检查 formula 类型字段
2. 用 `+field-get` 获取公式表达式
3. 检查引用的 field_id 是否存在
4. 发现问题 → 用已知模式修复（见下方修复手册）
5. 输出修复结果

---

## 已知修复模式

| 问题 | 表现 | 修复 |
|------|------|------|
| `COUNT(FILTER(...))` 嵌套 | "暂不支持的函数" | → `COUNTIF + SUMIF` |
| `AVERAGE(FILTER(...))` 嵌套 | "暂不支持的函数" | → `SUMIF / COUNTIF` |
| 引用已删除字段 | "公式引用的数据源已被删除" | 重建字段或改用现有字段 |
| 除零错误 | "除数不能为0" | 加 `IF(COUNTA(...)>0, ..., 0)` |
| 格式不匹配 | "计算结果和字段格式不匹配" | 加 `TONUMBER()` |

## 冲突解决规则

当 wiki 和 Base 数据不一致时：

1. **时间戳优先**：更新时间更晚的一方为准
2. **结构优先**：wiki 的知识框架不被 Base 数据覆盖
3. **数据优先**：Base 的数值数据不被 wiki 描述覆盖
4. **无法判断**：列在 neat-freak 变更摘要的"未处理"中让用户决定

## 每次 neat-freak 执行时的飞书检查清单

- [ ] 检查所有 formula 字段是否有报错
- [ ] 检查 wiki 修改是否已同步到 Base
- [ ] 检查 Base 重大变化是否已回写 wiki
- [ ] 检查视图字段顺序是否合理
- [ ] 输出飞书同步结果到变更摘要
