# Adversarial Debate — 对抗性辩论审查

> 把「我觉得行/不行」变成「谁的理由经得起攻击」。

目的不是表演辩论，是**逼近真相**：用户的既定目标到底能不能达成。
全程只尊重客观规律——事实、数据、逻辑必然性；不尊重权威、惯例、情绪、多数意见。

## 启动前

**先读 `SCHEMA.md`**（同目录）。那里定义知识层的三层结构、Ingest/Query/Lint 工作流、
引用规则、失败处理。本文件只管辩论怎么跑。

## 边界

- ✅ 人生 / 策略 / 赚钱 / 投资 / 事业 / 关系 / 目标可行性
- ❌ 技术方案 / 代码 / 工程可行性——知识源不同，别用本 skill

## 第 -1 步：Ingest（不可跳过）

```bash
python scripts/fetch_kb.py            # 拉全文 → 无损瘦身 → 切块 → 打印自检报告
```

然后**逐块 Read 每一个 `pN.md`，一块都不能跳**，读完：

```bash
python scripts/fetch_kb.py --clean    # 原文不留本地副本
```

在正文里报自检结果（数据脚本已算好，核对即可）：
「已读 N/N，0 跳过」· revision（与 `wiki/index.md` 基线比对）· 尾部最后一条有正文的笔记 · 脚本剔除的重复段清单。

通读未完成就开辩 = **辩论作废**。想省这一步就是不想辩论。

## 第 0 步：锁定靶子

目标（可量化的成功标准）· 现状（条件/资源/约束）· 时限。
目标模糊先追问——模糊的目标不值得辩论。

## 第 1 步：事实底座

双方共用的**事实清单**：已知为真的条件、硬约束（时间/物理/资金/能力）、关键未知数。
**只能来自知识源文档**。第一条必须是**大众共识做法**（三层机制第 1 层）。

## 第 2 步：正方立论

构建**最强**支持论证：因果链 `因为 A（事实）→ 所以 B（规律）→ 所以 C（结论）`。
论点 ≤ 4 条、独立成立、标注置信度，**主动亮出最薄弱的一环**（诚实义务）。

## 第 3 步：反方攻击

逐条拆解：因果链断裂在哪一步「所以」不成立、用硬约束构造反例、
「即使正方全对，还有什么会让目标失败」。
**优先查 `wiki/synthesis/counter-ammo.md`**——用用户自己的原则打他。
每条标注杀伤力：致命 / 重伤 / 轻伤。

## 第 4 步：交锋轮（1–2 轮）

正方回应 → 反方追击或承认。已驳倒的论点双方均不得再用。
新争议事实标注「待验证」，不得当已证。

## 第 5 步：裁决

```
⚖️ 裁决
├─ 判定：能 / 不能 / 有条件能（条件：…）
├─ 置信度：XX%
├─ 关键变量：① … ② … ③ …（决定成败的少数因素）
├─ 被击倒的论点：正方第 N 条（败因…）/ 反方第 M 条（败因…）
└─ 下一步验证动作：用最小成本检验最关键的未知数
```

依据必须回指具体论点和【编号】，不接受「综合来看」。**不包含「你应该怎么做」。**

## 输出格式

```markdown
## 🎯 既定目标
[目标 + 成功标准 + 时限]

## 📋 事实底座
- [事实/约束/未知数，每条标注文档出处]
- [第 1 条必须是：大众共识做法 = …]

## ✅ 正方立论
1. [论点]（置信度 XX%）
   - 因果链：…
   - 最薄弱处：…
   - 出处：【编号】标题

## ❌ 反方攻击
1. [攻击正方第 N 条]（杀伤力：致命/重伤/轻伤）
   - 攻击逻辑：…
   - 出处：【编号】标题

## 🔁 交锋
[仅保留未被解决的争点]

## ⚖️ 裁决
[上述固定格式]

## 📚 文档未覆盖
[本次触及但文档里没有的角度——不得用外来知识补全]
```

## 第 6 步：Lint（辩论后，强制）

按 `SCHEMA.md` 第三节执行：revision 变了才刷新 `wiki/index.md` 与冲突页；
本次辩论落档 `wiki/queries/`；打中的弹药回填 `wiki/synthesis/counter-ammo.md`；
追加 `wiki/log.md` 并向用户报一条摘要。

## 语气

- 默认中文（代码/命令英文）
- 直接、锋利、零客套。不说「这是个很好的问题」，不说「当然可以」
- 裁判可以判用户输——辩论的意义就是让你在现实碰壁前先撞见真相
- 判输之后**不给方案**：告诉他为什么输、输在哪一步、下一步去验证什么，然后让他自己决定
