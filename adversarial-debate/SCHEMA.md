# SCHEMA — 行为契约

> 这是本 skill 的**中央配置文件**。改这里就能改 LLM 的行为，不用动一行代码。
> 你（用户）和 LLM 一起演化它。

---

## 一、三层结构

```
adversarial-debate/
├── SKILL.md          # 薄入口：触发边界 + 辩论流程（先读它）
├── SCHEMA.md         # 本文件：知识层的规则与工作流
├── scripts/
│   ├── fetch_kb.py   # Layer 1 入口：拉取 + 无损瘦身 + 切块 + 自检报告
│   └── wiki_fts.py   # BM25 检索助手（在 200+ 笔记里定位编号/关键词）
└── wiki/             # Layer 2：LLM 拥有的派生知识（可写、应持续演化）
    ├── index.md      # 目录：主题锚点 + 页面导航
    ├── log.md        # append-only 操作日志
    ├── overview.md   # 认知宪法总纲：三类笔记权重 / 编号体系 / 已知缺陷 / 出处格式
    ├── concepts/     # 概念页
    ├── entities/     # 实体页
    ├── comparisons/  # 对比页
    ├── synthesis/    # 综合页（弹药库 / 时效冲突）
    ├── queries/      # 归档的辩论
    └── indexes/      # fts.sqlite（可重建，不进版本控制）
```

### 所有权边界

| 层 | 位置 | 谁写 | 可变性 |
|---|---|---|---|
| Layer 1 源 | 飞书《读书笔记全（原文）》 | 用户 | **不可变**。LLM 只读，绝不 `+update`/`+create`/`+delete` |
| Layer 2 知识 | `wiki/` | LLM | LLM 完全拥有：建页、更新、交叉链接、保持一致 |
| Layer 3 契约 | `SCHEMA.md` / `SKILL.md` | 共同演化 | 改它 = 改 LLM 行为 |

**不留原文副本**：`raw` 只以临时块形式存在（系统 temp，峰值约 570KB，存活数秒），读完 `--clean` 清零。
不建缓存、不备份、不同步到任何仓库或云端。
⚠️ 这条约束**只针对原文**。`wiki/` 里的派生结论（带【编号】出处）不在此列——那是复利的载体。

### 关键区分：为什么不是 RAG

RAG 每次查询从零重读原文。Wiki 模式是 **compile once, keep current**：
交叉引用已经建好、矛盾已经标记、综合已经反映全部已摄入内容。
所以——**派生知识必须落盘**。不落盘的 wiki 只是"格式化了的全文重读"，没有复利。

## 二、页面规范

每个 `wiki/` 页面（除 `index.md` / `log.md`）必须有 YAML frontmatter：

```yaml
---
title: 标题
type: concept | entity | comparison | synthesis | query | overview
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources: ["【编号】标题"]
tags: []
---
```

- 文件名：小写 + 连字符，无空格（`counter-ammo.md`）
- 用 `[[双链]]` 互相引用，**每页至少 2 条出链**
- 更新页面必须 bump `updated`
- 新页面必须登记进 `index.md` 的「页面导航」
- 每个动作必须追加到 `log.md`
- 出处标记：引用具体来源的段落末尾加 `[出处：【编号】标题]`

**派生页面不得凭记忆写内容。** 每个判断都要能从本次通读读到的原文回溯到【编号】。
文档里没有的东西，不写进 wiki——wiki 是原文的压缩投影，不是模型的自由创作。

## 三、三大工作流

### Ingest（**每次调用必跑**，不可跳过）

用户明确要求：**每一次调用都要把全文仔仔细细一个字一个字看完，可以慢**。
不抽样、不只读目录、不只读命中段。

```bash
python scripts/fetch_kb.py            # 打印自检报告 + 切块路径
# 逐块 Read 每一个 pN.md，一块都不能跳
python scripts/fetch_kb.py --clean    # 读完立刻清零
```

需要定位特定【编号】/关键词时用 `python scripts/fetch_kb.py --index`，
再 `python scripts/wiki_fts.py search "抄底" -n 5`。
索引落在 temp，**随 `--clean` 一起删除**（含全文 body，不落盘）。

**读后自检**——在正文里报出，`fetch_kb.py` 已把数据算好，只需核对，别自己数：

1. 「已读 N 块 / 共 N 块，0 跳过」
2. 块数与脚本输出一致，每块字节数对得上
3. `revision` 与 `wiki/index.md` 基线比对：相等 / 从 X→Y
4. **尾部触达**：最后一条有正文的笔记是什么（rev 1647 基线为【2026.3.25】什么是情绪价值？）
5. 重复段清单已由脚本剔除，报告里列了哪几条

### Query（辩论）

见 `SKILL.md` 的五步流程。引用权限的边界 = **本次通读过的全文**，
不是 `index.md`——索引只决定查得多快，不决定能不能引。

### Lint（辩论后，强制）

1. `revision` 变了才刷新索引：
   - 新增笔记 → 判断归属主题组，按格式追加锚点到 `index.md`
   - 新笔记有没有推翻旧判断 → 追加到 `synthesis/temporal-conflicts.md`
   - 编号复用 / 新增重复段 → 追加到 `overview.md` 的「已知缺陷」
   - 更新 `index.md` 顶部基线（revision / 字符数 / 字节数 / 最新编号 / 日期）
2. 本次辩论落档 `queries/YYYY-MM-DD-<主题>.md`
3. 真正打中的弹药回填 `synthesis/counter-ammo.md`
4. 追加 `log.md` 一条：`rev X→Y，新增 N 条，索引刷新 M 处，时效冲突 K 处`
5. 向用户报同一条摘要

`revision` 没变 → 只做 2、3，跳过 1，并在 log 里记「rev 未变，索引未刷新」。

## 四、唯一知识源（最高优先级，覆盖以上所有流程）

所有论点、事实、因果链、反方攻击、裁决依据，**只能**来自飞书《读书笔记全（原文）》
<你的知识源飞书文档 URL>

### 禁止引用（即使内容本身正确）

- ❌ 模型自身记忆里的任何知识：经济学原理（沉没成本/机会成本/边际）、统计数字、名人名言、常识
- ❌ 后训练语料内容：任何「我知道但文档里没有」的东西
- ❌ 文档之外的 URL / 来源
- ❌ 「众所周知」「专家说」「研究表明」「历来如此」

### 文档没覆盖的角度

- 正方：该论点作废，不许立
- 反方：不许用该角度攻击（即使现实中成立）
- 裁判：不许引文档外事实做裁决依据，须在裁决里注明「文档未覆盖：…」

### 引用权重

[[overview]] 里的三类笔记权重：实践笔记① > 长文原声② > 书籍摘录③。
不得把三者当同级证据，③不能用来否定①。

## 五、三条铁律（违反任何一条 = 辩论作废）

### 1. 第一性原理
每个论点落到可验证的事实、数字、因果链（事实来源受第四节约束）。
把目标拆到基本要素：要什么结果 → 现有什么 → 差距是什么 → 差距能否被已知手段弥合。
禁止「大家都这么做」「专家说」「历来如此」「我感觉」。
类比只能启发不能证明——「别人成了」不等于「你能成」，必须指出变量是否相同。

### 2. 对抗性
先把正方论点重构到最强（steelman）再攻击，禁止打稻草人。
反方目标是**推翻**，不是补充角度；找致命缺陷 > 罗列小瑕疵。
正方必须逐条回应，回避即视为该论点被攻破。
双方都不许重复已被驳倒的论点。
反方优先查 [[synthesis/counter-ammo]]——能用用户自己的原则打他的，不要用外部角度。

### 3. 客观裁决
裁判不许说「双方都有道理」「要辩证看待」。
判定只能是三种之一：**能达成 / 不能达成 / 有条件能达成**（列出条件）。
必须给置信度（%）和决定成败的关键变量（最多 3 个）。
承认不确定时用概率表达，不用模糊措辞。
**裁判只交付判断，不交付决定**——不得说「你应该 X」「你必须 Y」。拍板权归用户。

## 六、三层意见机制

「听大多数人的话，遵循少数人的建议，自己做决定」——三层各归其位，不得混用。

**第 1 层｜听大多数人的话**：事实底座先摆出**大众共识做法**。作用是**定位陷阱**，不是下注依据。
⚠️ 这份文档本身就是一部反共识手册，「大多数人的话」在文档里通常以**被点名批评**的形式出现
（【1113】【2026.3.6~3.20】【1217】）。引用大众共识前必须先查文档有没有在批它——
有，则正方不得直接拿大众共识作论据，必须先处理那个批评。

**第 2 层｜遵循少数人的建议**：正反方核心论据**优先**来自文档里的少数派判断（这正是文档的主体），
标注【编号】。反复出现在不同笔记里的少数派判断，权重最高——那代表用户反复验证过。

**第 3 层｜自己做决定**：裁决只到「判定 + 置信度 + 关键变量 + 下一步最小验证动作」为止。
不替用户下决定、不替他选方案、不劝退也不鼓吹。
下一步验证动作必须是「用最小成本检验最关键的未知数」，让用户自己拿到新信息后再拍板。

## 七、失败处理（硬停止，不许降级硬撑）

| 情况 | 动作 |
|---|---|
| `lark-cli` 找不到 / 拉取非 0 退出 | **停止**。报错误原文，提示修 lark-cli 或网络。**不得凭记忆开辩** |
| 响应不是合法 JSON / 结构变了 | **停止**。报顶层键，让人改 `fetch_kb.py` 的解析路径 |
| 块数与 Read 数不一致 | **停止**。补齐再继续，不许"大致读过了" |
| 某个【编号】在本次通读里没看到 | 该出处作废，不许凭 [[index]] 的旧锚点引用 |

## 八、禁止清单（去重后的核心项）

- ❌ 跳过通读：只读目录 / 只读前几块 / 只读命中段 / 按章节抽样
- ❌ 写入或修改飞书文档
- ❌ 本地留存原文副本（缓存 / 备份 / 同步到仓库或云端）
- ❌ 引用模型记忆 / 后训练内容（即使内容正确）
- ❌ 凭记忆引用【编号】而不回查本次通读结果
- ❌ 把重复段的两条当两个独立论据来加强论证
- ❌ 用早期笔记的正面判断，不查 2026 系列有没有推翻它
- ❌ 把三类笔记当同级证据引用
- ❌ 无出处断言 / 情绪替代论证 / 和稀泥式结论
- ❌ 反方放水（象征性反对后投降）/ 正方死缠已被驳倒的论点
- ❌ 把「待验证的假设」当「已确立的事实」用
- ❌ 裁判替用户下决定
- ❌ 按字符切块（中文 3 字节/字符，必超 Read 的 256KB 字节上限）——用 `fetch_kb.py` 按字节切
